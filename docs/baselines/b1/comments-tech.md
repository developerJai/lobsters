# Comments — Technical Documentation

Technical reference for the threaded commenting feature in Lobsters: posting, editing, voting, flagging, deletion/disowning, confidence-based thread ordering, read tracking, and reply/mention notifications.

## Components

| File | Role |
|---|---|
| `app/controllers/comments_controller.rb` | All comment HTTP actions (create, show, edit, update, reply, delete, undelete, disown, upvote, unvote, flag, index, upvoted, user_threads, short-id redirect/JSON) |
| `app/models/comment.rb` | Core model: validations, threading, confidence scoring, permission predicates, recursive-CTE thread queries |
| `app/models/comment_stat.rb` | Daily average comment score, precomputed for the `above_average` scope |
| `app/models/comment_vote_hydrator.rb` | Batch-loads the viewing user's votes, vote summaries, and replied-to state onto a comment collection |
| `app/models/read_ribbon.rb` | Per-user, per-story read tracking and reply-following toggle |
| `app/mailers/email_reply_mailer.rb` | Reply and mention emails with mailing-list threading headers |
| `app/jobs/notify_comment_job.rb` | Async delivery of reply and @mention notifications (in-app, email, Pushover) |
| `app/views/comments/` | Comment partial, comment box, preview, threads renderer, too-deep notice, newest/upvoted index, user threads, RSS builder |
| `app/views/email_reply_mailer/` | Plain-text reply and mention email bodies |

## Data model

`Comment` `belongs_to :user`, `belongs_to :story` (with `touch: true`), and optionally `belongs_to :parent_comment` (self-referential, `counter_cache: :reply_count`, `touch: true`) and `belongs_to :hat`. It `has_many :votes` (`dependent: :delete_all`), `has_one :moderation` (`dependent: :restrict_with_exception`), `has_many :links` / `:incoming_links` (both `restrict_with_exception`), and polymorphic `has_many :notifications, as: :notifiable`.

Key persisted attributes (from model usage): `short_id` (max 10 chars, unique, generated by `ShortId`), `comment` (raw markdown, max 16,777,215 chars), `markeddown_comment` (rendered HTML, regenerated by the `comment=` setter via `Markdowner.to_html`), `score`, `flags`, `confidence`, `confidence_order` (3-byte binary sort key), `thread_id`, `depth`, `is_deleted`, `is_moderated`, `is_from_email`, `last_edited_at`, `last_reply_at`, `reply_count`.

Virtual attributes (`attr_accessor`): `current_vote`, `current_reply`, `previewing`, `vote_summary` — populated per-request, usually by `CommentVoteHydrator`.

### Threading

- Top-level comments get `depth = 0` and a fresh `thread_id` from `Keystore.incremented_value_for("thread_id")`; replies inherit the parent's `thread_id` and `depth = parent.depth + 1` (`assign_initial_attributes`).
- `MAX_DEPTH = 18`: `depth_permits_reply?` returns false at depth ≥ 18 (and always for unsaved records). The controller renders the `too_deep` partial and files a `ModNote.tattle_on_max_depth_limit`; the model validation adds "You have replied too greedily and too deep."
- `COP_LENGTH = 31 * 3 = 93`: recursive CTEs (`Comment.story_threads`, `Comment.recent_threads`) build a fixed-width `confidence_order_path` by concatenating each ancestor's 3-byte `confidence_order`, giving a single lexicographic ORDER BY for an entire tree.
- `parents` returns all ancestors oldest-first via a recursive CTE keyed on `parent_comment_id` (works on new records).

### Confidence scoring

`calculated_confidence` implements the Wilson score lower bound (Evan Miller / reddit `_sorts.pyx`) at 80% confidence (`z = 1.281551565545`), using BigDecimal to avoid float error, clamped to `0..1`; deleted/moderated comments score 0. `update_score_and_recalculate!` recomputes `score` (sum of votes), `flags` (count of −1 votes), `confidence`, and `confidence_order` in raw SQL. `confidence_order` is 3 bytes: two big-endian bytes of `65535 − floor(confidence × 65535)` (so high confidence sorts first ascending) plus the low byte of the comment id as a stable tiebreaker. A noted race: two simultaneous votes may compute confidence without each other's score change.

### Constants

| Constant | Value | Meaning |
|---|---|---|
| `COMMENTS_PER_PAGE` | 20 | Page size on /comments and /comments/upvoted |
| `FLAGGABLE_DAYS` | 7 | Comments older than this cannot be flagged |
| `DELETEABLE_DAYS` | 14 (`FLAGGABLE_DAYS * 2`) | Author self-delete window; after this, disown instead |
| `FLAGGABLE_MIN_SCORE` | −10 | Comments at or below this score cannot be flagged further |
| `COLLAPSE_SCORE` | −5 | Comments at or below this score render collapsed |
| `MAX_EDIT_MINS` | 360 (6 h) | Edit window measured from `last_edited_at` |
| `MAX_DEPTH` | 18 | Maximum reply depth |
| `SCORE_RANGE_TO_HIDE` | −2..4 | Score hidden in this range while comment is under 36 h old |

## Lifecycle

### Creation (`CommentsController#create`)

1. Requires a logged-in user (`require_logged_in_user_or_400`). Story is looked up by `short_id`; missing or gone stories return 400.
2. Optional `hat_id` resolves against `@user.wearable_hats`; optional `parent_comment_short_id` must resolve to a comment on the same story (else JSON error "invalid parent comment").
3. Exact duplicates (same user, story, parent, body) are silently accepted and re-rendered — resubmits on slow connections.
4. **Speed limit** (`breaks_speed_limit?`, skipped for previews and moderators, replies only): delay = `(2 + flag_count + commenter_flag_count).minutes`, where flag counts come from flags on the ancestor chain (the author's own flags double-count). If the author commented in the same thread within the delay, an error "Thread speed limit reached, next comment allowed in …" is added, optionally appending "Is this thread getting heated?" and "You flagged here, you can leave it for mods."
5. On save: the author's upvote is recorded (`record_initial_upvote` creates a `Vote` with `vote: 1`, then `update_score_and_recalculate!`), `story.last_comment_at` is touched, parent's `last_reply_at` is set, and `NotifyCommentJob` is enqueued. `mark_submitter` bumps the `user:<id>:comments_posted` keystore counter. If validation fails or `preview` is set, the preview partial is rendered instead.

### Validations (model)

- `comment` presence ("cannot be empty.") and length ≤ 16,777,215; `short_id`, `confidence`, `confidence_order`, `flags`, `score`, `last_edited_at` presence.
- Low-effort filters, each a hard error: "this." → "Nope"; "tl;dr" → "Wow!  A blue car!"; quote-only bodies → "If a tree falls in the woods…"; "bump…" → "Don't bump threads."; spaced-capitals ("D O N ' T"); "me too"/"nice"/"+1" → "Please just upvote the parent post instead."; graphics/emoji-only → "🚫".
- Hat must be wearable by the author; parent must not be gone ("Comment was deleted by the author or a mod while you were writing."); depth must permit reply; story must be `accepting_comments?` ("Story is no longer accepting comments.").
- `validate_commenter_hasnt_flagged_parent` (on create): you cannot reply to a comment you have flagged ("You've flagged that comment for the mods, so you can leave it for the mods.").

### Editing

`is_editable_by_user?`: author only, comment not gone, and within 6 hours of `last_edited_at`. `#update` resets the hat from `hat_id`, sets `last_edited_at`, supports preview, re-touches parent `last_reply_at`, and for non-XHR requests redirects to the comment's target path. `has_been_edited?` is true when `last_edited_at − created_at > 1 minute` (renders "edited" in the byline).

### Deletion, undeletion, disowning

- `is_deletable_by_user?`: author only, within 14 days of creation. `delete_for_user` sets `is_deleted` and saves without validation.
- `delete_by_moderator`: additionally sets `is_moderated`, writes a `Moderation` record ("deleted comment", optional reason), and decrements author karma by `votes.count * −2`.
- `is_undeletable_by_user?`: any moderator; or the author when not moderated. `undelete_for_user` clears flags, restores score via `update_score_and_recalculate!(0, 0)`, and logs a Moderation when a mod undeletes someone else's comment. Timestamps are not bumped (`record_timestamps = false`).
- `is_disownable_by_user?`: author only, after the 14-day delete window; `#disown` calls `InactiveUser.disown!` to reassign the comment.
- `is_gone?` = deleted or moderated. `gone_text` renders "Comment removed by moderator <name>: <reason>", "Comment from banned user removed", or "Comment removed by author". Moderators still see the original text in views.

### Voting and flagging

`#upvote` / `#unvote` call `Vote.vote_thusly_on_story_or_comment_for_user_because` with 1 / 0. `#flag` requires a valid reason key in `Vote::COMMENT_REASONS` and `@user.can_flag?(comment)`, then votes −1 with the reason. `is_flaggable?`: not gone, not your own comment, score > −10, and age ≤ 7 days. The byline shows a vote summary (reason counts) to the comment's author, and reasons with usernames to moderators (`vote_summary_for_user` / `vote_summary_for_moderator`). `show_score_to_user?` hides scores on comments < 36 h old with score in −2..4, and always hides from a viewer who flagged the comment; moderators always see scores.

## Listings and feeds

- **`GET /comments` (`#index`)** — newest comments, 20/page, `accessible_to_user` (mods see deleted; others see `active` only), excluding comments on stories the user hid, tag-filtered, excluding deleted stories. Maintains a "Last Read" marker from `user.last_read_newest_comment` (carried across pages via `last_read_timestamp` param until shown). RSS: per-user private feed via RSS token, or a public feed cached 2 minutes (`comments.rss`). Page caching (`caches_page`) applies to `index`/`threads` when `CACHE_PAGE`.
- **`GET /comments/upvoted` (`#upvoted`)** — comments the user upvoted, excluding their own; has a real `@has_more` count; RSS supported; hidden stories not yet respected (TODO in code).
- **`#user_threads`** — the 20 most recent threads a user participated in (`Comment.recent_threads`), rendered as full trees in confidence order; redirects logged-out visitors to /active when no username given.
- **Permalinks** — `#show_short_id` returns `as_json` (short_id, timestamps, deleted/moderated flags, score, flags, parent short_id, HTML and plain body with `gone_text` substitution, depth, username, URLs). `#redirect_from_short_id` resolves `/c/<short_id>` to the story page anchor `#c_<short_id>` through a permanent Rails cache entry, following merged stories; admins may use numeric ids.

`find_comment` looks comments up by `short_id` only (numeric PK allowed for admins, deliberately avoiding enumeration) and hydrates `current_vote`, `vote_summary`, `current_reply` for the viewer.

## Read tracking (`ReadRibbon`)

One ribbon per (user, story): `is_unread?(comment)` is true when the comment postdates the ribbon's `updated_at` and isn't the user's own. `bump` updates the timestamp without callbacks/validations (performance; the model deliberately has no callbacks). `is_following` gates reply notifications per story (`hide_replies_for` / `unhide_replies_for`). `expire_old_ribbons!` deletes ribbons untouched for a year.

## Notifications (`NotifyCommentJob`)

Runs on queue `default` after comment creation; replies first, then mentions:

1. **Replies** — recipients: the story author (if `story.user_is_following` and not the commenter) and the parent comment's author (if active and not the commenter). Each gets an in-app `Notification`. Email (`EmailReplyMailer.reply`) and Pushover are sent only to users who have `email_replies?` / `pushover_replies?` and have **not hidden the story** (notifications are still created so unhiding reveals them; emails can't be recalled).
2. **Mentions** — `@username` or `~username` scanned from the body, minus the author and anyone already notified for the reply (email_replies trumps email_mentions to reduce duplicate email). All mentioned active users get a `Notification`; email/Pushover again respect story hiding and the `email_mentions?` / `pushover_mentions?` settings. Mail errors are swallowed.

`EmailReplyMailer` sets `Message-Id`, `References` (story + all ancestor comments), and `In-Reply-To` headers from `mailing_list_message_id` (`comment.<short_id>[.email].<created_at>@<domain>`), so mail clients thread correctly. Subjects: "[<site>] Reply from <user> on <story title>" / "[<site>] Mention from …". Bodies are plain text, word-wrapped at 72 columns, with a permalink.

## Rendering

- `_comment.html.erb` renders byline (avatar, user link, hat, edited/e-mailed marker, "(unread)"), action links (edit, delete/undelete/disown, mod delete, flag/unflag, reply, "on: <story>"), score (via `comment_score_for_user` / `upvoter_score`), and body. Collapse state: a checkbox is pre-checked (collapsed) unless `force_open`, viewer is a moderator, or `score > COLLAPSE_SCORE && !current_flagged?`. CSS classes `upvoted` / `flagged` / `replied` / `bad` (score < −2) mark state.
- `_threads.html.erb` walks a depth-ordered flat list and emits nested `<ol class="comments">` trees; it embeds an inlined copy of the comment partial ("heinous_inline_partial" — keep both copies in sync). Comments from merged stories get a merge icon and "on:" link.
- `_commentbox.html.erb`: Post/Update, Preview, Cancel buttons; "Put on hat:" selector when the user owns hats; markdown help; disabled textarea with placeholder "You must be logged in to leave a comment."; a closing-soon hint when the story nears its commenting cutoff.
- `comments/index.rss.builder` emits RSS 2.0 with TTL 120.

## Supporting tables

`CommentStat` stores one row per date with the day's average comment score (30-day rolling `daily_fill!`, dates offset −5 h, deleted comments excluded, upserted `on duplicate key update`). `Comment.above_average` joins it and falls back to an average of 3 where no row exists.

`CommentVoteHydrator` wraps any comment collection (Enumerable, delegates `size`/`length`/`empty?`/`any?`) and lazily decorates each comment with the viewer's `current_vote`, `vote_summary`, and `current_reply` from three batched queries — avoiding N+1 on listing pages.

## Gotchas

- `update_score_and_recalculate!` has a documented vote race (second concurrent vote ignores the first's score delta in confidence).
- `accessible_to_user` must only be used for flat listings; threaded rendering needs deleted placeholders to avoid misleading reply gaps.
- `#upvoted` does not yet respect hidden stories.
- The thread partial contains a manually inlined copy of `_comment.html.erb`; edits must be made in the source partial.
- Deletes/undeletes save with `validate: false` and suppress timestamp updates.
